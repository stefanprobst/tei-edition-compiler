# Edition IR v0.1 — first evidence-driven slice

Historical baseline: current output uses [IR v0.2](ir-v0.2.md), which adds required document order to parts and anchors. The v0.2 contract supersedes the version and array-order tie-break rules below.

Status: experimental, implemented for the three initial Auden–Musulin documents plus two pinned revision stress fixtures. Version is the literal `0.1`; incompatible changes require a new version. TEI is canonical. JSON outputs and snapshots are derived and disposable. This is a semantic compilation, not XML represented as JSON.

## Implemented interfaces

The authoritative executable contracts are Zod schemas in `packages/ir/src/index.ts`; TypeScript types derive from them. Schemas reject unknown object properties. The edition validator additionally checks unique IDs, typed internal references, mention labels, text-range bounds, parent positions and acyclic part/annotation containment.

```ts
Edition { version: '0.1'; id; documents; entities; mentions;
          relations; annotations; resources; anchors; diagnostics }
Document { id; metadata; parts; resourceIds; relationIds; annotationIds; provenance }
Part { id; kind; parentId?; parentOffset?; content?: { kind: 'text'; text: string };
       resourceIds; provenance }
Entity { id; kind; authorityRef; label?; resolution: 'external'; provenance }
Mention { id; entityIds; range; label; provenance }
Relation { id; subjectId; predicate; objectIds; externalTargets?;
           date?; description?; provenance }
Annotation { id; kind; targetIds; externalTargets?; parentId?; range?; body?; responsibility;
             certainty?; evidence; details; provenance }
Resource { id; kind: 'image'; uri; bounds?; provenance }
Anchor { id; partId; offset; resourceIds; label?; provenance }
Provenance { source; selector }
DateValue = { kind: 'exact'; value; label }
          | { kind: 'interval'; start?; end?; label }
          | { kind: 'text'; label }
```

Intervals require at least one nonempty bound. The runtime validator supports a deliberately limited Gregorian subset: years 0001–9999, year-month, full dates, and full timestamps with seconds, optional 1–3 fractional digits, and optional `Z` or a UTC offset up to ±14:00. It checks month/day validity and leap years, time components and offsets. It does not implement all TEI/ISO calendar syntax: BCE/year zero, expanded years, leap seconds, 24:00 notation, alternate calendars and other lexical forms need future mapping evidence. An exact value is exact at the precision supplied; it is not automatically a full timestamp.

Interval comparison respects source precision: a year/month/day or second/fraction describes a validation extent at that precision. Bounds are rejected only when the start's earliest possible value is later than the end's latest possible value. These extents are internal validation aids, never emitted as fabricated dates. Explicit-offset timestamps compare in UTC; civil dates and floating timestamps compare in civil order. Mixed civil/UTC bounds are not ordered because a timezone would have to be invented. Offset spelling and original precision remain unchanged in IR.

The compiler recognizes exact `when`/`when-iso`, start `from`/`from-iso`/`notBefore`/`notBefore-iso`, and corresponding end attributes. Conflicting values within a group, or an exact value combined with bounds, become textual values with `conflicting-date-attributes` diagnostics. Invalid or unsupported machine-readable values and reversed bounds become text with `invalid-date`; unsupported calendar/dating-method identifiers receive `unsupported-date-calendar`. The compiler conservatively recognizes only `gregorian` and `#gregorian`; other calendars are not silently converted. Text labels are retained, or attribute evidence supplies a fallback label. Completely empty dates produce an explicit “Unspecified date” display label and an `empty-date` diagnostic. Diagnostics carry the precise source element selector and machine-attribute evidence; these labels are fallbacks, not inferred historical dates.

Metadata dates come from origin/setting, not publication dates. Correspondence/setting relation dates use the same validator and diagnostic path. Body date text remains part of the transcription; no general calendar interpretation is inferred there.

Content is an explicitly normalized diplomatic reading: insertions and deletions both remain, each annotated; missing text emits U+FFFC and retains quantity/reason in an annotation. Uncertainty, substitutions, language changes, paragraphs, headings, verse lines and stanzas are range annotations. Whitespace-only indentation is discarded; other XML whitespace collapses to spaces, explicit line breaks become newlines, blocks end with a newline. No trim occurs after offsets are assigned. Ranges are half-open JavaScript UTF-16 offsets into the exact emitted part text; anchors point between code units. Nested parts have their own content, never duplicated into parent text. A nested part carries both `parentId` and `parentOffset` (a UTF-16 position in the parent's text) so consumers can interleave it with the parent's content; array order breaks ties at the same position. The transcript is an explicit containing part, including for the initial three fixtures, because prose stress tests demonstrate meaningful content between named components. Embedded texts are explicit parts rather than silently absorbed into surrounding prose.

Range annotations now have optional `parentId` for the nearest containing semantic annotation in the same part. This preserves substitution membership even when ranges coincide or spacing has zero width. Substitutions group their insertion/deletion annotations; nested substitutions retain their intervening deletion/insertion parents. Parent ranges must contain child ranges and both parent graphs must be acyclic. This is structural containment, not an inferred chronology of changes. Work references use the project-neutral entity kind `work`; quotations retain source references as evidence. This policy is not a reading-text edition or a layout facsimile.

Resources retain image service URIs and surface bounds without fetching images or assuming every URI is a downloadable image. Relative graphic URLs resolve at compile time against the source document URI and inherited `xml:base` declarations; valid absolute URLs can recover from an invalid inherited base. Invalid resource URLs are omitted with source diagnostics rather than aborting compilation. Surface coordinates must all be present, finite decimal numbers with nonnegative dimensions; incomplete, invalid or reversed bounds are diagnosed and omitted while retaining usable images. Bounds are computed once per owning surface, and nested surfaces do not duplicate graphics or inherit the outer surface's dimensions accidentally.

Page markers become independent anchors. A resource can occur at multiple anchors. Surface IDs, graphic IDs, encoded fragments, direct image URLs and document-qualified IDs for the current source/its aliases resolve at compile time. A surface with multiple graphics maps to multiple resources. Repeated pointers or overlapping surface/graphic references do not duplicate anchor resource IDs. Every distinct unresolved pointer receives a diagnostic even when another pointer on the same page resolves successfully. A page marker without a facsimile attribute is a valid image-free anchor; an explicitly empty attribute is diagnosed. A photograph can have an offset-zero anchor and no content.

Fragment-only facsimile references are intentionally source-local, independently of the image URL base. No remote image metadata, cross-document facsimile registry or region/zone model is inferred. Pointers to zones, undeclared image URLs or other source documents remain unresolved diagnostics; surface bounds are not claimed to be crop regions or pixel dimensions fetched from an image service. For portable relative URLs, callers should supply a real `Source.uri`; the virtual file URI fallback supplies identity, not a remote hosting location.

Entities are external authority references, deduplicated by complete canonical authority URI. Matching fragment names in different authority documents are distinct. `Mapping.authorityDocuments` explicitly assigns shared authority documents to entity kinds; the Auden preset maps person/place/organization/event/work fragments to the corresponding project indexes. These index names are supported by explicit `acdh:amp-index-*.xml#…` references in the fixtures. Fragment-only pointers use that configured scope; without it they remain document-local. Bare `sameAs` identifiers use the same fragment policy. Full URI references keep their original authority, and configured compact prefixes expand before identity comparison. No fragment or basename heuristic joins unrelated authorities. Mentions are independent occurrences. External correspondence documents use typed external relation targets, not invented local documents. Participant descriptions remain on relations. Unresolved entity records are deliberate; authority indexes are not vendored or fetched. Canonical entity labels remain unset until authority data supplies them: mention text such as “I”, “both men” or a revision-laden name is an occurrence label, not a canonical name. The canonical URI determines the entity ID independently of source order; entity provenance records the first occurrence, while every mention/relation retains its own provenance. Repeated equivalent pointers in a mention are deduplicated.

Contradictory known classifications for one authority URI emit `entity-kind-conflict` diagnostics and produce `kind: 'unknown'`, rather than silently selecting the first classification. An unknown classification alone does not contradict known evidence. Malformed authority pointers remain unresolved entity records with their raw reference, occurrence provenance and an `invalid-entity-reference` diagnostic; their fallback identity is source-scoped. Interpretation links point to structured annotation records, whose prose, responsibility identifiers, certainty and evidence links are retained. A single link record represents all pointers on one source occurrence; duplicate pointers and inverse part targets are deduplicated. Missing interpretations remain link records with original pointers as evidence and, when the pointer is parseable, `externalTargets: [{ kind: 'annotation', source: absoluteUri, selector }]`. The external selector is opaque provenance; runtime consumers do not execute XML selectors.

## Provenance and identity

Every emitted semantic object carries a source filename and selector. Selectors prefer XML IDs; otherwise namespace-aware traversal builds local-name sibling paths relative to the nearest ID. The compile-time selector notation assumes TEI namespace for unqualified path segments. Non-TEI elements use expanded segments `Q{encodedNamespaceUri}localName[position]`; an empty namespace is `Q{}`. Namespace URIs are percent-encoded within braces. This prevents a foreign element and a TEI element with the same local name from receiving ambiguous structural paths. Sibling positions count elements with the same expanded name, ignoring text, comments and other namespaces. Consumers only need to pass selectors back to a source resolver, not execute XPath. No runtime XML parser is required. Structural selectors are stable for identical bytes but can change when siblings are inserted. Source-byte identity is recorded in the fixture manifest; IR does not yet embed hashes or character-level source maps.

`createSourceIndex({ name, xml })`, exported by `packages/compiler`, supplies the same parser/selector implementation used by compilation. Its `selector(element)` and `provenance(element)` methods produce source references; `resolve(selectorOrProvenance)` returns the selected source element or `undefined`. A provenance object naming another source does not resolve. The resolver parses only this selector grammar: a JSON-quoted `id(...)` anchor with optional child steps, or an absolute structural path. It does not evaluate XPath or JavaScript. Malformed, unsupported and stale selectors return no element. Duplicate nonempty `xml:id` values anywhere in the source are compilation errors, including unmapped metadata, because ID-based provenance must be unambiguous. Nodes from a different source index are rejected by the selector generator.

This is compile-time/editorial tooling and returns DOM elements only to callers explicitly inspecting canonical source. DOM nodes never enter IR, and application consumers still need no XML parser. Treat indexed DOMs as read-only and rebuild the index when source changes. The index does not detect content edits behind an unchanged ID or verify a source hash; callers must use the expected source revision.

## Mapping boundary and limitations

The compiler uses a namespace-aware DOM and explicit semantic extraction, never a generic element serializer. `Mapping` configures division categories, optional element-to-part categories (used for embedded texts), and entity categories. The bundled Auden–Musulin mapping is a compile-time preset; the core schema contains no project IDs, TEI element names or namespaces. New projects can supply another mapping. Header extraction, text policy and editorial rules currently remain procedural in one small compiler. Interpretation resolution runs after all supplied documents have registered their annotations. It matches the full document URI and decoded fragment, not a basename or a global XML ID; repeated fragment IDs in different documents remain distinct. Target resolution is independent of source input order (the edition arrays still preserve source traversal order).

`Source.uri` optionally specifies an absolute document identity without a fragment. Otherwise the preset's `documentBaseUri` plus the document ID supplies identity; without that project setting, the source name resolves under a virtual `file:///` root. The source location is also registered as an alias. Relative pointers resolve against document identity. `referencePrefixes` expands explicitly configured compact URI prefixes before URI resolution; the bundled `acdh` prefix and base URI reflect the fixtures' declared project namespace. There is no basename fallback, network fetching or arbitrary `prefixDef` execution. XML base inheritance is implemented for facsimile resource URLs and pointers; interpretation/entity source identity still uses explicit source/mapping URI settings rather than a general XML-base mapping engine. Ambiguous document URI aliases are rejected rather than silently overwriting another document. Do not infer that arbitrary TEI is supported. Unmapped body elements emit diagnostics while their descendants are traversed; foreign elements are omitted with diagnostics. Text and page markers outside any mapped part now emit `unassigned-content` diagnostics rather than disappearing silently. Unknown referenced entity categories emit `unmapped-entity`. DTDs and declared entities are rejected.

Descriptive metadata is intentionally a subset: title, languages, origin dates, identifiers and rights; not every header field is compiled. Handwriting, physical placement, rendering, alternate readings, interventions and authority scopes need further evidence before generalizing. Source attributes retained as provenance, responsibility/evidence references or annotation detail values are opaque evidence; application behavior uses semantic kinds, not those source tokens.

## Open questions and next evidence

1. Should physical components, intellectual works and transcription occurrences become separate linked concepts? Two poem occurrences do not justify silently merging a work.
2. How should the now-tested 0028/0062 revisions become alternatives, sequence and reading policies? Explicit annotation containment preserves membership; current diplomatic text is not a revision graph.
3. Should content become typed blocks/inlines, or do text plus ranges suffice for accessible rendering? Validate against a real consumer before expanding.
4. How should supplied authority indexes enrich missing labels, names, identifiers and types? Explicit scopes, full URI identity and classification-conflict diagnostics are implemented; authority-record ingestion, aliases between distinct authority URIs and editorial reconciliation remain open.
5. Which assertion types need typed responsibility/certainty vocabularies, and how should annotation-to-annotation targeting evolve? Current strings preserve evidence without claiming an ontology.
6. Which additional calendar systems, uncertain/approximate date forms and precisions are justified by new source evidence? Open bounds, Gregorian validity and conservative precision-aware ordering are implemented; broader calendar interpretation remains deferred.
7. When should a declarative XPath mapping language replace procedural header extraction? First expand with contrasting TEI evidence; do not build a plugin framework preemptively.
8. What identity/source-map policy survives source edits? XML IDs take priority, structural paths are a fallback, not permanent identifiers across revisions.

Tests cover a full deterministic edition snapshot, pinned fixture checksums, compound hierarchy, photograph without text, relations/dates, anchored mentions, scholarly assertions, namespace-prefix invariance, configurable categories, XML rejection, diagnostics and invalid IR references/ranges. Stress tests additionally cover all 134 page anchors, 546 substitutions with explicit insertion/deletion membership, 13 nested substitutions, embedded text positions, work entities and quotation evidence. A compact stress-fixture snapshot complements the complete initial-edition snapshot. Snapshot updates require reviewing the semantic diff.

Known stress-fixture diagnostics: nine `unresolved-interpretation` occurrences when compiling 0028 and 0062 together. The second pass resolves four occurrences from 0028 to annotations in supplied 0062. The remaining nine point to documents outside the fixture set (0009, 0012, 0031 and 0053); they retain structured external targets, original evidence, source ranges and diagnostics. Missing fragments within supplied documents are also retained externally and diagnosed. Malformed or fragmentless pointers retain evidence and diagnostics without inventing a target. No source is fetched implicitly. Local interpretation links resolve as before. No `unassigned-content`, `unmapped-content`, `unmapped-entity` or unresolved-facsimile diagnostics remain for these five fixtures under the bundled mapping.

Reference tests cover source-order independence, document-local fragment scope, multiple pointers per occurrence, missing targets, unrelated authorities sharing basenames, relative file references, percent-encoded fragments, malformed pointers and ambiguous document identities.

Entity tests additionally cover cross-authority fragment collisions, document-local references, configured shared scopes, bare participant identifiers, percent-encoded fragments (including literal percent sequences), duplicate pointer tokens, conflicting/unknown classifications, malformed references and source-order-independent IDs.

Date tests cover precision preservation, Gregorian leap years and impossible dates, empty/open bounds, overlapping coarse precision, explicit UTC-offset ordering, floating/mixed timezone contexts, conflicting attributes, unsupported calendars, textual fallback with source diagnostics, and shared metadata/relation validation. The five pinned fixtures produce no date diagnostics and their existing snapshots are unchanged.

Provenance tests round-trip every element in all five fixtures and independently resolve every emitted provenance record (including diagnostics) within its declared source. Additional cases cover nearest-ID stability under ancestor sibling edits, namespace collisions/prefix changes, foreign and empty namespaces, malformed/stale selectors, duplicate XML IDs and cross-document node/source rejection. Existing edition snapshots are unchanged.

Facsimile tests cover relative URLs and inherited bases, surface/graphic and encoded/document-qualified pointers, multi-graphic surfaces, duplicate pointers, mixed resolved/missing targets, image-free page anchors, invalid coordinates/URLs, nested surfaces and recovery through absolute URIs. All five fixture outputs and their snapshots remain unchanged.
